# lingopress-ai


## 람다 사용 이유
```
우선 sentense transformer를 사용하려면 메모리나 컴퓨팅 파워가 많이 소요된다.
ec2 인스턴스에 올려서 사용해보니, 백엔드 api가 느려지는 현상이 발생했다.
그렇다고 프리티어를 사용하는 상황 상 성능을 높일 수는 없다.
그러면 람다를 사용해보자 싶었다. 
지난번 스크래핑 프로젝트에서 람다를 사용하려다, 라이브러리 호환성 문제로 실패했던 경험이 있어,
찾아보니, 도커를 사용하면 해당 문제도 해결하고 대용량 도커 이미지도 올릴 수 있다고 한다.

마침 인스턴스에서 사용해보려고 만든 이미지도 거의 9GB에 가까워서, 도커로 올리기에 적합하다고 생각했다.

자료들을 몇가지 조합하였다.

우선 참고 자료 1을 기반으로 fast api로 만든 서비스를 도커 이미지로 만들어 람다에 사용할 수 있도록 하였다.
여기서 docker build 시 --platform을 사용하는 부분은 제외하였다. 
라이브러리 호환성 문제 때문에 이미지가 만들어지지 않는 것이 문제였다.
또한, api gateway와 연결하는 것도 중요하다.

그리고 참고 자료 2를 통해 모델을 미리 다운 받고, 이를 활용하는 법과,  
pytorch도 cpu만 사용하는 버전을 다운받아야한다는 점도 참고하였다.

참고로 이미지 한번 빌드할 때마다 1~20분은 잡아먹으니, 실수하지 않도록,,하는 것이 좋다. 

그리고 람다 설에서 메모리를 최대한 올려주는 것이 좋다.


이 작업하는데 6시간 정도 사용한 거면.. 나름 괜찮은거같기도....
```
